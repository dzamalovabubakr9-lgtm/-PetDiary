## Исправления, внесённые при ревизии

- Закрыт доступ без авторизации ко всем представлениям дневника и процедур.
- Закрыто редактирование профиля без входа.
- Добавлена уникальность email пользователя и явная роль `user/admin`.
- Исправлен декоратор проверки роли (использует поле роли пользователя и правильный URL входа).
- Исправлена ссылка подтверждения штатного Django password reset.
- Добавлена автосоздача профиля при регистрации.
- Добавлена серверная проверка принадлежности питомца пользователю в формах дневника/процедур и сериализаторах API.
- Добавлены JWT API-эндпоинты регистрации, входа, обновления токена и восстановления пароля.
- Добавлен ИИ-помощник с приватной историей диалога и контекстом питомцев.
- Добавлены настройки SMTP/ИИ через `.env`, `.gitignore`, psycopg 3 и production security settings.
- Исправлена POST-форма выхода вместо GET-ссылки.

## Что обязательно сделать перед сдачей

1. Создать `.env` по `.env.example`, указать секретный ключ, PostgreSQL и при необходимости SMTP/ИИ-ключи.
2. Установить зависимости; выполнить `python manage.py check`, `makemigrations --check --dry-run`, `migrate`, `test`.
3. Проверить миграции на PostgreSQL, не на SQLite.
4. Прогнать Postman/cURL для 200/201/400/401/403/404/422 и проверить запрет доступа к чужим данным.
5. Проверить сброс пароля по реальной тестовой почте и добавить отдельную модель хешированных одноразовых токенов, если строго следовать требованиям тем 7 и 13.
6. Проверить адаптивность 320/768/1920 px, доступность и браузеры; сохранить скриншоты.
7. Добавить ERD/UML, отчёты по отсутствующим темам, заключение, презентацию и доклад.
8. Создать Git-репозиторий, добавить remote и отправить коммиты.

**Ограничение проверки:** `python manage.py check` и тесты не удалось запустить в среде ревизии: модуль Django отсутствует. Поэтому внесённые изменения прошли синтаксическую проверку Python, но не считаются подтверждёнными интеграционными тестами.
