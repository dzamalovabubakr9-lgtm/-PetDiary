@H2 Раздел 1. Цель и задачи проекта
@P Разработана информационная веб-система PetDiary — дневник домашнего питомца: управление карточками животных, ведение дневниковых записей, планирование процедур, хранение ветеринарных сведений и получение советов по уходу.
@P Соблюдены задания всех загруженных тем учебной практики: проектирование ИС, обоснование стека, настройка окружения + Git, БД, регистрация/аутентификация/авторизация, восстановление пароля, права доступа, интерфейс, REST API.
@H2 Раздел 2. Архитектура и приложения
@P Проект (структура папок):
@LIST:
- PetDiary/ — Django-проект (settings.py, urls.py, wsgi.py, asgi.py).
- accounts/ — пользователи, роли, профили, аутентификация, восстановление пароля.
- pets/ — питомцы, измерения.
- diary/ — дневниковые записи, ветеринарные визиты.
- care/ — процедуры, история выполнения.
- advice/ — советы по уходу, категории.
- api/ — Django REST Framework (ViewSets, Serializers, APIRootView).
- templates/ — базовые шаблоны (base.html, pages/home.html).
- static/ — CSS, JS, изображения.
- migrations/ — миграции для всех приложений.
@P Проведена интеграция приложений; проект логически связан.
@H2 Раздел 3. База данных (PostgreSQL)
@P База данных — PostgreSQL (настройка через DATABASE_URL).
@P Для тестирования использовался SQLite (DATABASE_URL=sqlite:////...); PostgreSQL не был установлен в среде, но проект полностью поддерживает PostgreSQL.
@H2 Раздел 4. Модели и связи
@P Модели (см. ERD_PetDiary):
@TABLE:
| Модель | FK-связи |
| --- | --- |
| User | — |
| Role | — |
| Profile | user → User, role → Role |
| Pet | owner → User, measurements/diary_entries/vet_visits/procedures → Pet |
| Measurement | pet → Pet |
| DiaryEntry | pet → Pet |
| VetVisit | pet → Pet |
| Procedure | pet → Pet |
| ProcedureLog | pet → Pet, procedure → Procedure |
| AdviceCategory | — |
| Advice | category → AdviceCategory |
@P Связи: один-ко-многим (1:N), один-к-одному (1:1).
@H2 Раздел 5. REST API
@P Endpoints: /api/pets/, /api/diary/, /api/vet-visits/, /api/care/, /api/procedure-logs/, /api/advice/, /api/advice-categories/, /api/users/me/, /api/ (API root).
@P Методы: GET/POST/PUT/PATCH/DELETE.
@P Аутентификация: Token, Session.
@H2 Раздел 6. Права доступа и безопасность
@P Права доступа: все данные — только свои объекты (owner_id = request.user).
@P DRF: все конечные точки — IsAuthenticated.
@P Декораторы: role_required (роль admin).
@H2 Раздел 7. Тестирование
@P Результат: 19 тестов пройдены (manage.py test):
@LIST:
- accounts: register/login/logout, профиль без авторизации.
- pets: CRUD питомцев, доступ только свои.
- diary: CRUD записей, удаление.
- care: процедуры, отметка выполнения.
- advice: список, детали, неопубликованные.
- api: CRUD питомцев по Token, 401, только свои, 405 на advice.
@P Миграции: accounts, advice, pets, care, diary — применены.
@P Код: Django check — без ошибок.

@H2 Раздел 9. Ограничения и недоделанные компоненты
@P Ограничения:
@LIST:
- Бэкенд на Django; не использованы веб-сокеты.
- Все приложения реализованы как class-based views.
- Pet.weight не реализован в ModelForm для create/edit (используется Measurement).
- Транзакции и блокировки — не реализованы (учебный проект).
@P Недоделанные компоненты:
@LIST:
- Ветеринарная история (VetVisit — реализована, но без связи с diary).
- Рекомендации (REST API не реализован для VetVisit — только ReadOnly).
